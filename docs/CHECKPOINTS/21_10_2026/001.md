## 7. CMS Y WEB STUDIO

### Archivos conocidos

Editor CMS original:

`frontend/dashboard/cms.html`

Este archivo es un editor reconocido del proyecto. Debe preservarse hasta definir y autorizar una intervención específica.

JavaScript del editor:

`editor/cms_editor/app.js`

Adaptador CMS:

`backend/api/cms_adapter.py`

El JavaScript consulta una API local en:

`http://127.0.0.1:8000`

Rutas consumidas por el editor:

- `GET /templates`
- `GET /clientes`
- `POST /generate_cms`

La interfaz obtiene plantillas y clientes, permite seleccionar una plantilla y envía datos como `brand_name`, `hero_title` y `hero_subtitle`.

Cuando la respuesta de generación indica éxito, el editor configura el `src` de un iframe de vista previa usando `output_url`.

Esto describe el comportamiento observado en el código; todavía debe comprobarse que la API esté levantada, que sus rutas coincidan y que la generación completa funcione.

### Adaptador CMS

Archivo:

`backend/api/cms_adapter.py`

Rutas de almacenamiento definidas por el adaptador:

- Plantillas: `templates/core_templates`
- Clientes: `storage/clientes`
- Resultados: `storage/output`

Funciones observadas:

- `list_templates()`
- `list_clients()`
- `generate(template_id, data, client_id=None)`
- `save_preview(html)`

`generate()` carga el HTML de la plantilla, combina datos de cliente con los datos enviados, aplica valores predeterminados y reemplaza marcadores `{{CLAVE}}` escapando valores mediante `html.escape`.

El adaptador incorpora alias como MARCA, MARCA_RESALTADA, HERO_TITULO, HERO_SUBTITULO y TITULO, además de algunos valores predeterminados asociados a cursos, imágenes, login y metodología.

No asumir que esos alias y valores predeterminados son compatibles con todas las plantillas. Es necesario inspeccionar sus marcadores reales.

La función `save_preview()` guarda una salida HTML en una carpeta nueva dentro de `storage/output`. Antes de usarla, verificar el flujo y las consecuencias de escritura.
